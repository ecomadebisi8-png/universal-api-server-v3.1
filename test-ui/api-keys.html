API keys

Service-to-service credentials. The plaintext key is shown exactly once at creation — only its SHA-256 hash lives in D1.

✨ Create a key
POST /api/v1/auth/api-keys — write methods require read+write (or admin) permissions.
The new key is auto-saved into this browser session for X-API-Key calls. Save it somewhere safe too — it cannot be recovered.
📋 Your keys
GET /api/v1/auth/api-keys — metadata only. Hashes never leave the database.
🧪 Permission playground
Watch the API key rules bite: read-only key on a write endpoint → 403.
GET/api/v1/project-alpha using active key
POST/api/v1/project-alpha/items read-only key → 403
GET/api/v1/project-alpha using session JWT instead
🗺️ Endpoint map
GET/api/v1/auth/api-keyslist (masked)
POST/api/v1/auth/api-keyscreate
DEL/api/v1/auth/api-keys/:idrevoke
All three require a valid user JWT (API keys can't manage API keys).
